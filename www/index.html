orbit.lisp - pine

the idea

No black boxes.

A normal machine is a stack of programs you cannot see into. Each has its own config language. They pass text between one another and little else. When one breaks you route around it, because the inside is not yours to change.

pine is the inverse. A single Common Lisp image runs your tools, your interface, and your code, and every part of it is open and live. You do not configure it from the outside. You edit it from within.

why it holds

live

Recompile a function and live callers pick it up. Change a panel and watch it repaint. The running system is what you ship, not a build of it.

walled

Risky work runs in its own OS process, supervised. Let it crash, loop, or eat all memory: the rest never feels it. And its live restarts come home for you to choose. Genera's isolation, with the debugger intact.

yours

One language for all of it: Common Lisp on SBCL. Conditions, native speed, real FFI, macros, the MOP. The environment bends to you, not the reverse. Write your own anything.

the same image

Your desktop, too.

The bar, the panels, the gauges draw straight to Wayland from that same image. The shell is not a separate program. It is Lisp you rewrite while it is on screen.

no ceiling

You will not outgrow it.

Every environment eventually fights you: the config hits a wall, the extension API runs out, the one thing you need is not exposed. pine has no edge like that. It is Common Lisp all the way down to the render loop, so "can it do X" is never a question of what the authors allowed. You add it, and it becomes a first-class part of the system, not a plugin on the side.

The longer you use it, the more it is yours.

get it

Runs on Linux and Wayland.

Built with Guix and SBCL. One command brings up the daemon with the editor and desktop attached.
