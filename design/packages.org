#+TITLE: pine packages, symbols, and the naming that is wrong
#+AUTHOR: Bret Horne
#+OPTIONS: toc:2

A review of every package and the symbols that leak between them, and a plan to
fix the names that collide. Generated by listing the live external symbols, not
from memory.

STATUS: the renames this document prescribes are DONE (pine.cell -> pine.ref,
the surface disambiguation: pine.display for the painter, layouts for projected
buffers, surface = wayland placement only). Kept as the record of why.

* The map

** substrate
- =pine.server= :: the server object and its registries (actor-system, buffer,
  agent, faces, layouts, remoting-port).
- =pine.actor= :: agents -- spawn / supervise / eval isolated SBCL processes, and
  the registry and debug relay.
- =pine.agent= :: the code a spawned agent runs (=connect=).
- =pine.attach= :: the seam a client connects through; app kinds, push-to-app.
- =pine.eval= :: off-thread evaluation and the restart/debugger model.
- =pine.event= =pine.hooks= =pine.jobs= :: bus, lifecycle hooks, background jobs.

** buffers and the display grid
- =pine.buffer= :: buffers, state, snapshots, windows, and FRAMES. A frame is a
  grid of display cells (=frame-cells=, the flat 10-slot char+colour+attr
  array). Also faces and themes.
- =pine.client= :: per-client session state (windows, frame, completion,
  kill-ring, terminals).
- =pine.render= :: buffer -> frame (cells) -> rows (the wire); the renderer actor.

** editor
- =pine.editor= =pine.mode= =pine.keymap= =pine.key= =pine.command= =pine.echo=
  =pine.file= =pine.repl= :: the editor: commands, modes, keymaps, key parsing,
  dispatch, minibuffer, files, repl.

** widgets, style, data
- =pine.layout= :: the widget engine. Nodes, measure/arrange/paint over a raster
  of display cells, the constructor DSL, the wire codec, hit-testing. Holds
  =cells-view= (a leaf that carries pre-rendered display cells).
- =pine.cell= :: REACTIVE cells -- a named value that dedups and notifies. The
  eww-var. Nothing to do with display cells.
- =pine.source= :: data sources (=defpoll= / =defsource=) that feed reactive cells.
- =pine.style= :: the CSS-as-data resolver.
- =pine.palette= :: the completion facility (sources, actions, palette-tree).

** desktop and backends
- =pine.desktop= :: named shown regions (=defsurface=), show/hide panels.
- =pine.display= :: the cell-grid PAINTER -- =paint-rows=, =render-frame-to-png=,
  plus a dead abstract =surface= class with =present= / =paint-frame=.
- =pine.cairo= :: the cairo widget-tree backend.
- =pine.wayland= =pine.wl-editor= =pine.wlr-layer-shell= :: the wayflan client, its
  editor, and the generated layer-shell bindings.
- =pine.gtk= =pine.desktop-app= :: the GTK editor and desktop (the fallback).

** user
- =pine.user= :: the config vocabulary written in init.lisp.
- =pine= :: the CLI and daemon entry.

* The names that are wrong

** "cell" means two unrelated things
This is the one to fix now.

- The DISPLAY cell: the char + fg + bg + attr atom of the screen grid.
  =pine.buffer:frame-cells=, =frame-cell-count=, =ensure-frame-cells=;
  =pine.layout='s raster and =cells-view= / =cells-rows= / =blit-row=;
  =pine.display:paint-cell-grid=. This is the display substrate; everything
  renders into it.
- The REACTIVE cell: a named value that notifies on change.
  =pine.cell= (=cell=, =defcell=, =cell-ref=, =set-cell=, =make-cell=,
  =find-cell=, =update-cell=, =cell-of= in =pine.source=). This is the eww-var.

They share the word and have no relationship. A reader cannot tell
=cell-ref= (read a reactive value) from =frame-cells= (the screen grid) by the
name. That is the rot.

** "surface" means three things
- =pine.display= :: the cell-grid painter (and a dead abstract target class).
- =pine.desktop:defsurface= / =*surface-client*= / =set-surface-role= :: a named
  shown region (bar, panel, editor).
- =wl_surface= (in =pine.wayland=) :: the wayland object.

Overloaded, though less dangerous than cell because the wayland one is namespaced.

* The plan

** now: kill "cell" for the reactive concept
The display cell keeps the word -- a character grid atom is a "cell" in every
terminal, and it is the more pervasive, correctly-named use. The reactive value
becomes a =ref= (a reactive reference). Not =signal= (CL's condition system),
not =atom= (CL), not =var= (=pine.var=), not =box= (the layout widget) -- all
taken.

Rename =pine.cell= -> =pine.ref=, and its symbols:

| now              | ->            |
|------------------+---------------|
| =cell= (struct)    | =ref=           |
| =defcell=          | =defref=        |
| =make-cell=        | =make-ref=      |
| =find-cell=        | =find-ref=      |
| =cell-ref=         | =deref=         |
| =set-cell=         | =set-ref=       |
| =update-cell=      | =update-ref=    |
| =cell-value=       | =ref-value=     |
| =cell-name=        | =ref-name=      |
| =cell-subscribe=   | =ref-subscribe=   |
| =cell-unsubscribe= | =ref-unsubscribe= |
| =pine.source:cell-of= | =ref-of=     |

Reactive VIEWS (=make-view=, =render-view=, =reactive-view=, =dispose-view=) keep
their names; they are views, not cells. In the config vocabulary the reactive
read by name is =ref= and the definer is =defref=; =set!= stays as the setter.

After this, "cell" appears only for the display grid, and every reactive symbol
says =signal=. No reader confusion, no churn to the display path.

The user never types the display leaf name either: the vocabulary exposes
=buffer= and =terminal= (the two cell sources that matter); =cells-view= stays an
internal node name.

** next (not now): resolve "surface"
=pine.display= is really the cell painter; fold =paint-rows= /
=render-frame-to-png= into =pine.render= (or rename the package to =pine.paint=)
and delete the dead =surface= class. Then the only "surface" left is the shown
region, and if that becomes =view= (=defview=), "surface" disappears from pine
except as the wayland object it names. Deferred until the cell rename lands.
