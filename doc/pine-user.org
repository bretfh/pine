#+TITLE: The Pine User Language
#+AUTHOR: Bret Horne
#+OPTIONS: toc:2 num:t

The vocabulary you write in =init.lisp=. One language for defining surfaces and
their content, whatever Wayland backs them with. There is no editor language and
no desktop language; a surface is a surface, and a buffer is a widget you place
in one. The daemon loads =init.lisp= at boot, in the =:pine.user= package, and
this is the set of symbols it makes available.

Every name in this language is a symbol. Strings are for user facing text and
for shell commands, nothing else.

* Status legend

Each entry is tagged with where it stands against this design.

- [have]   usable now, this name and shape.
- [rename] exists, but under a different name or shape; needs to be brought to
  the name here.
- [build]  does not exist yet.

* Surfaces

A surface is the unit Wayland shows. You declare what you want; pine chooses the
backing primitive (layer-shell, xdg-shell, a subsurface). The editor, the bar,
and every panel are surfaces.

| symbol       | form                                   | status  |
|--------------+----------------------------------------+---------|
| =defsurface= | =(defsurface NAME (:as ROLE opts) BODY)= | [rename] |
| =show=       | =(show NAME)=                            | [rename] |
| =hide=       | =(hide NAME)=                            | [build]  |
| =toggle=     | =(toggle NAME)=                          | [rename] |

- =defsurface= NAME is a symbol. BODY returns a widget tree. Today it takes a
  string name and a builder function of an argument; the target is a symbol name
  and a body, with placement declared, not implied.
- =:as= ROLE is a placement preset: =:bar= =:panel= =:overlay= =:window=
  =:background= =:echo=. =:bar= is a layer surface anchored and exclusive;
  =:window= is xdg-shell; and so on. Raw options when you need them: =:anchor=
  =:layer= =:exclusive= =:size= =:margin=.
- =show= / =hide= / =toggle= take the surface symbol. Today this is =show-panel=
  keyed by string.

* Widgets

The base classes. The same set builds every surface. A widget takes =:class= and
=:face= for style and the event keywords under Behavior.

** Containers

| symbol       | note                                  | status  |
|--------------+---------------------------------------+---------|
| =column=     | vertical stack                        | [have]   |
| =row=        | horizontal stack                      | [have]   |
| =centerbox=  | start / center / end along an axis    | [have]   |
| =center=     | center one child                      | [rename] |
| =box=        | fixed width cell                      | [rename] |
| =scroll=     | clipped, scrollable viewport          | [rename] |
| =grid=       | fixed column grid                     | [build]  |
| =stack=      | z-overlay, children on top of children | [build]  |

- =center= is =centered=, =box= is =boxed=, =scroll= is =viewport= today.

** Content

| symbol   | note                     | status  |
|----------+--------------------------+---------|
| =label=  | a text run               | [have]   |
| =icon=   | a glyph, optionally clickable | [have] |
| =image=  | an image from a path     | [rename] |
| =rule=   | a separator line         | [have]   |
| =gap=    | flexible empty space     | [have]   |

- =image= is =pic= today.

** Controls

| symbol   | note                           | status  |
|----------+--------------------------------+---------|
| =button= | a clickable wrapper            | [have]   |
| =slider= | a value gauge, drag to set     | [rename] |
| =ring=   | a circular gauge               | [have]   |
| =field=  | a text input                   | [build]  |
| =choice= | a selectable row               | [have]   |
| =rows=   | a list built by mapping a function over data | [have] |

- =slider= is =meter= today.

** Views

The widgets that dissolve the editor / desktop split: a buffer and a terminal
are widgets you place in a surface like any other.

| symbol     | note                                  | status  |
|------------+---------------------------------------+---------|
| =calendar= | a month grid                          | [rename] |
| =buffer=   | a buffer's live frame as a widget     | [build]  |
| =terminal= | a pty view as a widget                | [build]  |
| =modeline= | the mode line for a buffer view       | [build]  |
| =echo=     | the echo / minibuffer line            | [build]  |

- =calendar= is =cal= today.
- =buffer=, =terminal=, =modeline=, =echo= are the real work behind this
  language. Today a buffer frame and a widget tree are separate render paths
  (=pine.render= for the cell grid, =pine.layout= for widgets). Making =buffer= a
  layout node unifies them, and after that the editor is just
  =(defsurface editor (:as :window) (buffer (current)) (modeline) (echo))=.

* Style

Color and shape as data. Change the theme and everything downstream re-resolves.

| symbol       | form                              | status |
|--------------+-----------------------------------+--------|
| =deftheme=   | =(deftheme NAME :palette .. :metrics .. :faces ..)= | [have] |
| =defface=    | =(defface NAME :fg .. :bg .. :bold ..)= | [have] |
| =load-theme= | =(load-theme NAME)=                 | [have] |
| =color=      | =(color ROLE)=                      | [have] |
| =metric=     | =(metric KEY [default])=            | [have] |
| =face-fg=    | =(face-fg NAME)=                    | [have] |

- On a widget or a layout-buffer node: =:class= applies the CSS-as-data rules
  (styles the cairo panels and the cell render alike); =:face= applies a
  theme face directly. Both resolve to the same cell colours.

| symbol     | form                                       | status |
|------------+--------------------------------------------+--------|
| =defrules= | =(defrules (SELECTOR PROP VALUE ..) ..)=   | [have] |

- =defrules= appends to the one stylesheet; user rules win the cascade, and
  redefining a selector replaces it. VALUES are evaluated, so =(color :accent)=
  resolves against the active theme. Rules broadcast to every attached
  frontend, so the pixel painters restyle live too. =(defrules
  (".cand-row.sel" :background-color (color :bg-active)))=.
- =:opacity= is a rule property; a window view's glass is styled like
  anything else: =(window "scratch" :class "editor-view")= plus =(defrules
  (".editor-view" :opacity "0.9"))= -- re-eval the rule and the next frame
  repaints with it.

* Data

Sources feed refs; refs feed widgets. Reads inside a surface body are tracked,
so the surface re-renders when a ref it read changes, and only then.

| symbol      | form                                | status  |
|-------------+-------------------------------------+---------|
| =defref=    | =(defref NAME [default])=             | [have]   |
| =ref=       | =(ref NAME [default])= -- setf-able    | [have]   |
| =defpoll=   | =(defpoll NAME SECONDS BODY)=         | [have]   |
| =defsource= | =(defsource NAME COMMAND PARSE)=      | [have]   |
| =sh=        | =(sh COMMAND)= run a shell command   | [rename] |

- =ref= is the one accessor: a surface body that reads a ref re-renders when
  it changes, and =(setf (ref NAME) V)= writes it (deduped), creating it if
  missing. No separate setter.

* Behavior

What input does.

| symbol       | form                             | status |
|--------------+----------------------------------+--------|
| =defcommand= | =(defcommand NAME (args) BODY)=   | [have] |
| =:on-click=  | widget keyword                   | [have] |
| =:on-change= | widget keyword (slider)          | [have] |
| =:hint=      | widget keyword (echo hint)       | [have] |

* Keys

Emacs voice. A =defcommand= is reachable by key once bound.

| symbol           | form                          | status |
|------------------+-------------------------------+--------|
| =kbd=            | =(kbd "C-x C-f")= -> key(s)    | [have] |
| =keymap=         | =(keymap :global \vert :mode-kw)= | [have] |
| =define-key=     | =(define-key WHERE (kbd ..) CMD)= | [have] |
| =global-set-key= | =(global-set-key (kbd ..) CMD)=  | [have] |

- =kbd= parses a chord ("C-x C-f", "M-.", "Return") into a key or a sequence.
  WHERE is a keymap, =:global=, or a mode keyword. CMD is a command name string.

* Modes

=defmode= / =defminor= make a real CLOS class named NAME and register a mode
=:NAME= with its own keymap. Behaviour is plain CLOS on the class.

| symbol              | form                                        | status |
|---------------------+---------------------------------------------+--------|
| =defmode=           | =(defmode NAME (:parent :mode :indicator .. :ts-language ..) BODY)= | [have] |
| =defminor=          | =(defminor NAME (:precedence N :transparent B :indicator ..) BODY)= | [have] |
| =dispatch-message=  | =(defmethod dispatch-message ((m NAME) self tag plist) ..)= | [have] |
| =execute=           | =(defmethod execute ((m NAME) command arg) ..)= | [have] |
| =auto-mode=         | =(auto-mode "ext" :mode-kw)=                 | [have] |
| =enable-minor-mode= | =(enable-minor-mode :mode-kw)=              | [have] |
| =disable-minor-mode=| =(disable-minor-mode :mode-kw)=             | [have] |
| =toggle-minor-mode= | =(toggle-minor-mode :mode-kw)=              | [have] |

- The class NAME (a symbol) is what you specialise defmethods on; the keyword
  =:NAME= is what =set-buffer-mode= / =auto-mode= / the toggles take. A major
  mode's keymap is parented to its =:parent='s, so parent keys still resolve.
  Reload-safe: redefining replaces the class and the mode.

* Editor variables

Buffer-local-with-global-fallback settings, fset-backed.

| symbol            | form                                       | status |
|-------------------+--------------------------------------------+--------|
| =defonce=         | =(defonce :name :default V :documentation ..)= | [have] |
| =var=             | =(var :name [buffer])= -- setf-able         | [have] |

- =defonce= semantics: redeclaring updates the default and doc but keeps a
  value already set, so reloading =init.lisp= never clobbers it. One setf-able
  accessor, no separate setters: =(setf (var :tab-width) 2)= sets the global,
  =(setf (var :tab-width buf) 2)= sets it buffer-locally.

* Prompts and echo

| symbol           | form                                   | status |
|------------------+----------------------------------------+--------|
| =completing-read=| =(completing-read PROMPT CANDIDATES CB)= | [have] |
| =read-file-name= | =(read-file-name PROMPT CB)=            | [have] |
| =prompt=         | =(prompt PROMPT CB)= (a plain string)   | [have] |
| =message=        | =(message STRING)= to the echo area     | [have] |

- CB is a function of the chosen string. CANDIDATES is a list of strings or
  candidate objects. These make a =defcommand= interactive.

* Layout buffers (tool buffers)

A buffer whose content is a node tree: the same widget language as a panel,
rendered into cells, with selectable rows and per-row actions. (A buffer can
show a layout; a window shows a buffer; a surface places it.)

| symbol                 | form                                        | status |
|------------------------+---------------------------------------------+--------|
| =show-layout=         | =(show-layout NAME BUILDER [:mode M :selection N])= | [have] |
| =layout-select=       | =(layout-select DELTA)=                     | [have] |
| =layout-activate=     | =(layout-activate)=                         | [have] |
| =layout-node-at-point=| =(layout-node-at-point)=                    | [have] |

- BUILDER is a function of the buffer state returning a node tree. =choice= rows
  carry =:data= (a thunk); =layout-activate= (Return, via layout-mode) runs the
  row's thunk. =layout-select= (Up/Down/C-n/C-p) moves the highlight. A tool
  buffer is thus: =defcommand= + =show-layout= + =choice= rows + a keybinding.

* Processes

Isolated, supervised SBCL images. An agent's error ships its restart list home to
the editor, where you pick a restart and it resumes in its own image.

| symbol       | form                       | status |
|--------------+----------------------------+--------|
| =defagent=   | =(defagent NAME BODY)=      | [have] |
| =spawn=      | =(spawn NAME)=             | [have] |
| =supervise=  | =(supervise NAME)=        | [have] |
| =kill=       | =(kill NAME)=             | [have] |

- =defagent= is spawn plus supervise plus a body run in the agent's own image.

* The CLI

The shell face onto the same command surface. =pine VERB ARGS= is one binary that
is the daemon, a control client, and the launcher, the way =tmux= is server and
client and =systemctl= is control verbs over a channel. It is a CLI, not a REPL:
each invocation connects to the running daemon, issues one request, prints the
reply, and exits. The verbs are the vocabulary: =pine show bar= is the shell form
of =(show bar)=.

** Lifecycle

| verb            | does                                    | status |
|-----------------+-----------------------------------------+--------|
| =pine start=    | start the daemon if it is not running   | [build] |
| =pine stop=     | stop the daemon                         | [build] |
| =pine restart=  | stop then start                         | [build] |
| =pine status=   | up or down, port, attached clients, agents | [build] |

** Command surface (mirrors the vocabulary)

| verb                    | does                              | status |
|-------------------------+-----------------------------------+--------|
| =pine eval FORM=        | eval one form in the daemon, print it | [build] |
| =pine run COMMAND ...=  | run a named command (M-x from the shell) | [build] |
| =pine show NAME=        | show a surface                    | [build] |
| =pine hide NAME=        | hide a surface                    | [build] |
| =pine toggle NAME=      | toggle a surface                  | [build] |
| =pine set REF VALUE=    | set a ref                         | [build] |
| =pine reload=           | reload init.lisp                  | [build] |

** Agents

| verb                | does                | status |
|---------------------+---------------------+--------|
| =pine agents=       | list process agents | [build] |
| =pine spawn NAME=   | spawn an agent      | [build] |
| =pine kill NAME=    | kill an agent       | [build] |
| =pine logs NAME=    | an agent's output   | [build] |

** Buffers and frontends

| verb                | does                          | status |
|---------------------+-------------------------------+--------|
| =pine buffers=      | list buffers                  | [build] |
| =pine open FILE=    | open a file in a buffer       | [build] |
| =pine editor=       | launch the editor, attached   | [build] |
| =pine desktop=      | launch the desktop, attached  | [build] |

The control verbs (everything but lifecycle and the frontend launchers) connect
to the daemon over the same remoting the frontends use, ask one message of a
control actor, print, and exit. The frontend launchers are the =make= targets as
subcommands.

* The three decisions this catalog commits to

1. Names are symbols, everywhere: surfaces, refs, agents, commands. Strings only
   for user text and shell.
2. =buffer= and =terminal= are widgets. This is what makes it one language: the
   editor is a surface holding a =buffer=, and a =buffer= can sit in a panel. It
   is also the largest piece to build, because it unifies the two render paths.
3. One =surface= with =:as= presets. The layer-shell / xdg difference appears
   only in =:as=; the body is the same widgets either way.

* A sketch, in the target language

#+BEGIN_SRC lisp
(in-package :pine.user)

(load-theme :ef-dream)

(defpoll clock 1 (get-universal-time))
(defsource workspaces "niri msg --json event-stream" #'parse-workspaces)

(defsurface bar (:as :bar)
  (centerbox :orient :v
    :start  (column (icon #xF02C1 :on-click (sh "niri msg action toggle-overview"))
                    (rows (ref workspaces) #'ws-tile))
    :end    (column (icon #x0F028 :on-click (show audio))
                    (label (fmt-clock (ref clock)))
                    (icon #x0F007 :on-click (show ctl)))))

(defsurface editor (:as :window)
  (buffer (current)) (modeline) (echo))

(defcommand scratch () (show-buffer "*scratch*"))
(bind "C-c s" 'scratch)

(defagent notifier
  (loop (dolist (n (poll-notifications)) (emit n)) (sleep 1)))
#+END_SRC
