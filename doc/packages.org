Generated from the live package list, not from memory.

* The rule

The path to a package is its name. =pine.editor.keymap= lives in
=src/editor/keymap.lisp= and declares itself at the top of that file. There is
no manifest: =src/package.lisp= is gone.

A directory whose name is a package holds only that package's files, and none
of them repeats the directory name. A directory whose name is not a package is
a group, and every file directly in it is one package.

One exception, deliberate: =src/wayland/protocol/= is =pine.wayland.protocol=
over four files, because each file is a =wl-include= of one protocol XML and
the generated symbols have to share a namespace for the backing to use them.

* The check

=tests/deps.lisp= reads the source off disk, blanks comments and strings,
builds the package graph and fails on any strongly connected component larger
than one. It matches =pkg:sym= references, so a call through =:use= or an
unqualified same-package call is invisible to it: it checks the part that is
written down.

* The map

** src/ -- the daemon's own
- =pine= :: the CLI and the daemon entry (=src/pine.lisp=).
- =pine.user= :: the vocabulary a config writes in init.lisp.
- =pine.term= =pine.source= =pine.desktop= =pine.wm= =pine.frontend= ::
  one file each at the root, because each is one package.

** core/ -- the substrate
=pine.core.server= =pine.core.eval= =pine.core.actor= =pine.core.agent=
=pine.core.attach= =pine.core.event= =pine.core.hooks= =pine.core.jobs=

The actor system and its registries, off-thread evaluation and the debugger
model, process agents, the seam a frontend attaches through.

** state/ -- durable and reactive values
=pine.state.world= (how anything persists: values, bounded lists, and the
snapshot/revive methods a subsystem answers) =pine.state.store= (the sqlite
file under it, and world is its only caller) =pine.state.ref= (reactive cells)
=pine.state.var= (editor variables, persisted through world)

** text/ -- buffers
=pine.text.buffer= (state, snapshot, the actor, the registry)
=pine.text.window= (a window on a buffer, and the cell grid)

** ui/ -- the widget engine
- =pine.ui.node= :: the node classes and their slots. The layer =:use=s this.
- =pine.ui.build= :: the constructor DSL. Shadows =ring= and =centerbox=,
  the two names that are both a class and a constructor.
- =pine.ui.raster= :: the cell buffer widgets paint into.
- =pine.ui.layout= :: measure / arrange / paint, hit-testing, tree surgery.
- =pine.ui.cells= :: a node tree rendered to styled cell rows.
- =pine.ui.wire= :: the wire codec and rows-patch.
- =pine.ui.face= =pine.ui.css= =pine.ui.style= :: faces and themes, the
  user stylesheet, the CSS resolver.
- =pine.ui.render= :: buffer -> grid -> rows, the renderer actor.

=pine.editor.mode= =pine.editor.edit= :: mode classes, =defmode= /
=defminor=, the =dispatch-message= protocol, and the base/text verb methods.

=pine.editor.frame= :: one attached display's editing state -- its windows,
current buffer, kill ring, prefix argument, minibuffer, terminals, and which
modes are active.
