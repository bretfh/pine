#+TITLE: pine: the API
#+AUTHOR: Bret Horne
#+OPTIONS: toc:3 num:nil

This is the design. Nothing in =src/= implements it yet; the tree is rewritten
against this document, not the other way round.

* What this is

Unix has no vocabulary. The mixer is a CLI, the compositor is a JSON socket, the
battery is a file, the player is dbus, the editor is an image full of CLOS. Each
one exposes the same handful of things and names none of them, so every program
that wants to sit above them writes the same glue again in its own words.

pine is one namespace, one data model, and three verbs.

#+begin_src lisp
(read  PATH)
(write PATH VALUE)
(watch PATH FN)
#+end_src

A facsimile layer binding Unix, toward however you want to write Common Lisp.

* The ideas it rests on

Everything in this document follows from these. If something below contradicts
one of them, the thing below is wrong.

** Common Lisp is the extension language

The namespace is where state lives. That is all it is for. Your package is
ordinary CL: functions, macros, CLOS, conditions, an =.asd=. The DSL is maybe a
tenth of any real package, and it is the tenth that says where state goes and
what reacts to it.

** State is addressable, not private

A buffer's content, its point, its locals, its marks are paths. Nothing has to
be exported for something else to read them, nothing needs a =snapshot= method to
be persisted, and another image can read them without an accessor being written
for the occasion.

** Nothing refreshes

A view reads the paths it shows. When one moves, the view is rebuilt. There is no
=g=, no =revert-buffer-function=, no subscribe step, and no cached copy to go
stale.

** nil is nothing

It already means that in CL, so it means it here. Writing =nil= to a file path
deletes the file. Writing =nil= to a process declaration stops it. Reading a path
with nothing there answers =nil= and is not an error, because a namespace is not
a lexical environment.

** A pattern selects; Lisp computes

A path denotes a set. Selecting is the path language's whole job. Ordering,
aggregating, joining and limiting are what you already have every CL function
for, and building them into the path language is where this design would rot.

** Everything that runs answers writes

A command, a key, a click, a watch, a mode's newline: a pure function from the
namespace to a map of writes. Nothing performs an effect except a provider. So
everything is testable by calling it and comparing a map, with no daemon and no
wayland.

** Values are state; verbs are events

A value that does not change is not a change: no watcher fires, no surface
repaints. A verb always happens. That is why clicking twice works.

* Data

** Three literals

pine's readtable adds Clojure's three, backed by fset's persistent structures.
There are no plists and no alists anywhere in pine, at any layer, including the
wire.

| literal      | is             | example                     |
|--------------+----------------+-----------------------------|
| ={k v ...}=  | persistent map | ={:fg :yellow :bold t}=     |
| =[a b ...]=  | persistent seq | =[:insert "hello"]=         |
| =#{a b ...}= | persistent set | =#{:paren :flycheck}=       |

=[]= means a seq and nothing else, anywhere, including inside a path. A verb is a
seq whose head is a keyword, which is not a second meaning.

** Why, and it is not taste

The whole engine rests on one question: did this value change. On persistent
structures an unchanged subtree *is* the same object, so the answer is a pointer
compare and a tree diff descends only into what moved. On plists it is =equal=,
which is linear and blind to sharing, and every surface repaints every tick.

The same property gives the system its transactions, its history and its undo.

** The namespace is one map

=/= holds a nested persistent map. A path is a lookup into it. A write produces a
new root that shares everything it did not touch.

#+begin_src lisp
(read /)                  ; the entire state of the system, as one value
(read /audio)             ; => {:volume 40 :muted nil :sink "hdmi"}
(read /audio/volume)      ; => 40
#+end_src

A directory and a map are the same thing seen from two sides. Writing a map to a
directory writes its leaves, merging its keys; =[:set MAP]= replaces the subtree.

#+begin_src lisp
(write /audio {:volume 40 :muted nil})
(write /audio/volume 40)
#+end_src

* Paths

** Literals

=/= is a reader macro with its own syntax inside it, which is why a path's
constraints and ordinary map literals never collide: one lives inside a path,
the other is ordinary code. A path is self evaluating, case preserving, printable
and readable back, so it is data like any other.

#+begin_src lisp
/audio/volume
/buf/scratch/point
/win/0/weight
#+end_src

** The syntax inside one

| form         | means                                                 |
|--------------+-------------------------------------------------------|
| =*=          | one segment, any value                                |
| =**=         | any depth                                             |
| =#{a b c}=   | one of these                                          |
| =?name=      | bind one segment                                      |
| =?@name=     | bind the rest                                         |
| =${form}=    | evaluate; the value is one segment                    |
| =$@{form}=   | evaluate; a path, seq or slash-bearing string splices |
| ={k v}=      | constrain by the value there                          |
| =.=          | the current path                                      |
| =..=         | the parent                                            |

#+begin_src lisp
/win/${n}/buf
/net/wifi/?ssid/signal
/audio/#{volume muted}
/proc/*{:state :failed}
/file/$@{(namestring p)}
/host/*/theme
./signal                       ; relative to the current path
#+end_src

** Constraints

A constraint map's value is a pattern. A literal is equality, a set is
membership, =?name= binds, and a list is a CL form with =%= bound to the value.
Nothing is capped; it is Lisp.

#+begin_src lisp
/proc/*{:state :failed}
/proc/*{:state #{:failed :stopped}}
/net/wifi/*{:signal (> % 60)}
/wm/windows/*{:title (search "Firefox" %)}
/buf/*{:file (and % (string= "lisp" (pathname-type %)))}
/buf/*{:modified t}
/buf/*{:mode ?m}                    ; binds m for the right-hand side of a write
#+end_src

=%= rather than =_=, because =_= means "do not care" in every pattern language
anyone has used, and here the thing is very much cared about.

** A pattern only matches what exists

It never creates. So a fan-out write can update nine things and can never conjure
nine things, and generating paths is a loop in your code, where a loop belongs.

#+begin_src lisp
(dotimes (n 9)
  (write /key/wm/s-${(1+ n)} {/wm/workspaces/${(1+ n)}/focused t}))
#+end_src

** A path denotes a set

Which is why there is no =ls=. A pattern read answers a map from path to value,
and a map already gives you the names.

#+begin_src lisp
(read /audio/volume)   ; => 40
(read /audio/*)        ; => {/audio/volume 40 /audio/muted nil /audio/sink "hdmi"}
(read /proc/*/state)   ; => {/proc/editor/state :running /proc/desktop/state :running}
(read /**/err/*)       ; every fault, in every image, on every host
(keys (read /buf/*))   ; the buffer list
#+end_src

** Selecting versus computing

The pattern selects. Everything after that is CL on a map, and these are the
things that are deliberately not path syntax:

#+begin_src lisp
;; ordering -- a set has no order
(sort (keys (read /buf/*{:file (not (null %))})) #'>
      :key (fn (b) (read (path b :size))))

;; aggregating
(reduce #'+ (vals (read /proc/*/rss)))

;; joining two subtrees
(remove-if-not (fn (w) (find (read (path w :app)) (vals (read /proc/*/name))
                             :test #'equal))
               (keys (read /wm/windows/*)))

;; limiting
(subseq (by-recency (read /recent/*)) 0 5)
#+end_src

If a path had to answer those it would grow ORDER BY, LIMIT and JOIN. Select with
the pattern; it is a map after that.

** Taking one apart

#+begin_src lisp
(parent /buf/scratch/point)      ; /buf/scratch
(leaf   /buf/scratch/point)      ; "point"
(under  /buf /buf/scratch/point) ; ["scratch" "point"]
(path   /buf name "text")        ; when even the shape is computed
#+end_src

* The verbs

** read

#+begin_src lisp
(read PATH)
(read PATH DEFAULT)
#+end_src

Pure. Answers a value for a literal path, a map for a pattern. Inside a =write=
body or a handler, a =read= is recorded: see Re-evaluation.

** write

#+begin_src lisp
(write PATH VALUE &key on every keep max when force)
(write MAP        &key ...)
#+end_src

Answers what it changed, as a map of path to =[old new]=, or an empty map.

| option    | means                                                      |
|-----------+------------------------------------------------------------|
| =:on=     | also re-evaluate when this path, or set of paths, changes  |
| =:every=  | also re-evaluate on this interval, in seconds              |
| =:keep=   | =nil= to opt a held path out of durability                 |
| =:max=    | a ring of at most N entries; writes push                   |
| =:when=   | apply only if the path still holds this; compare and set   |
| =:force=  | permit a write the safety rules would otherwise refuse     |

** watch

#+begin_src lisp
(watch PATH FN &key as)
#+end_src

=FN= is a handler: called with the new value, answers a map of writes. Watching a
pattern watches every path it matches, including ones that appear later. =:as=
names the watch, so registering it again replaces it, which is what makes
re-loading a config safe; =(watch PATH nil :as NAME)= removes it.

* Values and verbs

A written value is either a literal or a verb. A seq whose head is a keyword is a
verb applied to what is already there; anything else is the new value. To write a
literal seq that would read as a verb, use =[:set X]=.

#+begin_src lisp
(write /audio/volume     40)                  ; a value
(write /audio/muted      [:toggle])           ; a verb
(write /buf/scratch/text [:insert "hello"])
(write /win/focused      [:split :below])
(write /proc/editor      [:restart])
(write /power            [:suspend])
(write /net/wifi/${ssid} [:connect])
(write /err/${id}        [:restart :abort])
#+end_src

A value write de-duplicates: writing what is already there changes nothing and
wakes nobody. A verb write never de-duplicates, because a verb is an event.
Toggling twice toggles twice, and a click always fires.

Which verbs a path takes is the provider's business and is answered by
=(read /doc/$@{path})=. There is no control file: a control file was a second
vocabulary for acting on the thing you already have a name for.

** A map is a transaction

The namespace is one persistent map, so a multi-path write is one new root. There
is no intermediate state, one repaint happens, and nothing ever observes the
system half changed.

#+begin_src lisp
(write {/audio/volume        40
        /audio/muted         nil
        /surface/audio/shown t})
#+end_src

** Fan out

A pattern in write position writes every match, with its binders in scope on the
right.

#+begin_src lisp
(write /win/*/weight 1)                                  ; balance the splits
(write /buf/*{:modified t :file (not (null %))} [:save]) ; save what is dirty
(write /proc/*{:state :failed} [:restart])               ; the whole of supervision
(write /host/*/theme :ef-dream)                          ; every machine
#+end_src

* Handlers

Anything that runs later is a function from the namespace to a map of writes.

#+begin_src lisp
(fn () {/win/focused/buf /buf/scratch})

(fn (v) (if (> v 90) {/notify {:text "battery full"}} {}))
#+end_src

=fn= is =lambda= with a seq arglist. A handler answers a map and pine applies it
as one transaction. It performs nothing itself, which is what makes it testable:

#+begin_src lisp
(assert (= (funcall (read /cmd/scratch))
           {/win/focused/buf /buf/scratch}))
#+end_src

No daemon, no wayland, no subprocess, no mocking.

When a handler is only its writes, the map alone is the handler:

#+begin_src lisp
(write /cmd/scratch {/win/focused/buf /buf/scratch})
(write /cmd/mute    {/audio/muted [:toggle]})
#+end_src

A widget's =:click= and a key binding both take either, or a command path.

** The effect boundary

Nothing performs an effect except a provider answering a write, so the set of
things that can touch the machine is the set of mounted providers. It is
listable, and it is the same set on every host.

* Re-evaluation

One rule, and it is every reactive mechanism pine had:

#+begin_quote
The expression written to a path is evaluated again whenever a path it read
changes.
#+end_quote

#+begin_src lisp
(write /greeting (format nil "~a@~a" (read /sys/user) (read /sys/host)))
#+end_src

reads two paths, so it recomputes when either moves, and anything that read
=/greeting= recomputes after that. A surface is not special: it is a path holding
a widget tree, and it repaints because its tree was rebuilt, cheaply, because the
parts that did not move are the same objects.

An expression that reads nothing is evaluated once, at the write. =:every= and
=:on= add triggers that are not value reads.

#+begin_src lisp
(write /sys/load (parse-loadavg (read /file/proc/loadavg)) :every 3)
(write /wm/workspaces (niri-workspaces) :on /sh/${"niri msg --json event-stream"})
#+end_src

Cycles are cut at the write that closes them and the path is marked; the fault is
at =/err=.

* Safety

Nothing is prevented. Everything is recoverable, visible before it happens, and
loud when it is large.

** Look before you write

=write= answers what it changed. =preview= answers the same map without applying
it. Since handlers are pure, a command can be inspected before it is ever bound.

#+begin_src lisp
(preview (write /buf/*{:modified t} [:save]))
;; => {/buf/init.lisp/modified [t nil] /buf/notes/modified [t nil]}
#+end_src

** The rules that refuse

| rule                                                     | escape        |
|----------------------------------------------------------+---------------|
| a pattern write from the CLI or REPL lists its matches and asks | =-y=, =:force t= |
| =**= at or above the root is refused                     | =:force t=    |
| a path no provider declares writable errors, with the path in the message | none |
| a write that would empty a non-empty ring is refused     | =:force t=    |

Refusal is about awareness, not permission. You can write anything. You cannot
write it without being told what it will touch.

** Concurrency

=:when= is compare and set, so two images racing on a path is a value question
rather than a lock.

#+begin_src lisp
(write /buf/notes/text new :when old)
#+end_src

* Persistence

** Three kinds of path, and only one is stored

The rule is not a flag you have to remember. It follows from where the value came
from.

| kind        | came from                                            | stored |
|-------------+------------------------------------------------------+--------|
| **live**    | a provider reading the world: =/sys= =/proc= =/wm= =/file= | never; the world is the storage |
| **derived** | a =write= whose expression read other paths          | never; recomputed |
| **held**    | someone wrote a value and nothing else determines it | yes, by default |

Held is kept unless you say otherwise, because "remember to persist this" is how
an editor ends up with a dozen private save paths. =:keep nil= opts out.

This gets buffers right with no special case. A buffer with a =:file= has text
derived from the file, so what is stored is its file, point, mode and marks, and
it re-reads on revive. A buffer with no file has held text, so the text is
stored.

** Rings

=:max= makes a ring: writes push, a read gives the newest, a pattern read gives
all. The kill ring, prompt histories, recent files and save-place are this.

#+begin_src lisp
(write /kill "text" :max 60)
(read  /kill)      ; the newest
(read  /kill/*)    ; the ring
#+end_src

** The store

One sqlite file per pine, on the host. One file, one tree, one identity. It is
this pine's world and its whole purview on this host.

#+begin_src sql
create table held (
  path  text    not null,
  seq   integer not null default 0,   -- 0 for a value, 1..n for a ring
  value text    not null,             -- readable lisp
  at    integer not null,
  primary key (path, seq)
);

create table changes (                -- bounded; retention is a held path
  n     integer primary key,
  path  text, old text, new text, at integer
);

create table self (id text, name text, since integer);
#+end_src

Held paths write through as they change; boot reads =held= in. The in-memory side
needs nothing from the file, because the namespace is a persistent map and this
session's roots are already sitting there. The file holds the durable tail.

#+begin_src lisp
(read /history)                    ; the roots, newest first
(read /was/${t}/win/*)             ; the arrangement as of t
(diff /was/${t} /)                 ; everything that moved since
(write / [:revert ${t}])           ; the world, back
#+end_src

There is no world facility, no snapshot protocol, no journal and no save format.
Undo of a paste and undo of a window split are the same operation because they
are the same kind of thing.

* Identity, and other pines

A pine needs a stable name that is not the hostname, because a hostname is not
unique and it changes.

#+begin_src lisp
(read /self)
;; => {:id "01J8Z...-a3f" :name "arraniz" :host "arraniz" :since ...}
#+end_src

=:id= is generated once at first boot and held. =:name= is what other pines
address you by and defaults to the hostname, so nothing is configured on a single
machine.

=/host/?name= is another pine. Your own name resolves locally, so every path in
this document works host-qualified or bare.

#+begin_src lisp
(write /host/arraniz (pine "arraniz:17000"))
(read  /host/arraniz/audio/volume)
(write /host/arraniz/buf/notes/text [:insert "from here"])
(write /host/*/theme :ef-dream)
#+end_src

** Sync is a write, not a merge

Moving state between pines is explicit, because the moment two pines can both
write =/theme= and something has to decide, this becomes a distributed systems
project instead of a Lisp Machine.

#+begin_src lisp
(write /host/arraniz/theme (read /theme))     ; push one path
(write /host/arraniz/mode  (read /mode))      ; push a subtree
#+end_src

Copying a file is a read and a write, which means it works across hosts with
nobody writing networking:

#+begin_src lisp
{/host/arraniz/file/backup/notes.org (read /file/home/bfh/notes.org)}
#+end_src

That reads the file into the image, which is right for anything a person edits
and wrong for a 4GB image, so there is a verb that lets the two providers
negotiate directly:

#+begin_src lisp
{/host/arraniz/file/media/x.iso [:copy /file/tmp/x.iso]}
#+end_src

Same shape, no bytes through the middle.

* Providers

Writing a provider to a path binds the subtree beneath it. That is the whole
extension mechanism, and it is a write like any other.

#+begin_src lisp
(write /audio  (pipewire))
(write /net    (networkmanager))
(write /sys    (procfs))
(write /wm     (niri))
(write /media  (mpris :player "emms"))
(write /buf    (buffers))
(write /host/arraniz (pine "arraniz:17000"))
#+end_src

The editor is a provider. The desktop is a provider. The window manager is a
provider. Another pine is a provider. None of them is the centre, and nothing
above a provider learns that there is a subprocess, a socket, a poll, a cache or
a file behind it.

** Writing one

=provider= takes path patterns. A pattern binds its =?name= segments, =.= is the
matched path, and =value= is bound in a =:write= body.

#+begin_src lisp
(write /audio
  (provider
    {:on  /sh/${"pactl subscribe"}
     :doc "pipewire, through wpctl and pactl"}

    (/audio/volume
     {:read  (fn () (percent (first-number (sh "wpctl get-volume @DEFAULT_AUDIO_SINK@"))))
      :write (fn (v) (sh "wpctl set-volume @DEFAULT_AUDIO_SINK@ ~a%" v))
      :doc   "0..100"})

    (/audio/muted
     {:read  (fn () (and (search "MUTED" (sh "wpctl get-volume @DEFAULT_AUDIO_SINK@")) t))
      :write (fn (v) (sh "wpctl set-mute @DEFAULT_AUDIO_SINK@ ~a" (if v 1 0)))
      :verbs {:toggle (fn () {. ${(not (read .))}})}})

    (/audio/sinks/*  {:read (fn () (sink-map (leaf .)))})

    (/audio/sink
     {:read  (fn () (sh "pactl get-default-sink"))
      :write (fn (v) (sh "pactl set-default-sink '~a'" v))})))
#+end_src

A pattern with no =:write= is read only. A provider with no =:on= is polled at
the rate its readers ask for. =:doc= is what =(read /doc/$@{path})= answers, and
it is the system's only documentation, so it lives beside the code that answers.

** Overlays

Writing a provider over an occupied path stacks it: reads fall through to the one
underneath for paths the top does not answer. That is how one machine's config
overrides a single leaf of a shipped provider without forking it.

#+begin_src lisp
(write /sys (provider (/sys/temp {:read (fn () (my-weird-sensor))})))
#+end_src

| =/env=     | the environment                               |
| =/clock=   | time                                          |
| =/audio=   | sinks, volume, mute                           |
| =/screen=  | outputs and backlight                         |
| =/power=   | battery, and the power actions                |
| =/net=     | connectivity, wifi, interfaces                |
| =/media=   | what is playing                               |
| =/wm=      | the compositor                                |
| =/surface= | what pine draws on wayland                    |
| =/win=     | pine's own windows: the arrangement           |
| =/buf=     | buffers                                       |
| =/mode=    | modes                                         |
| =/key=     | keymaps                                       |

| =/history= | the roots                                     |
| =/host=    | other pines                                   |

** /sys

| path                  | read                                       |
|-----------------------+--------------------------------------------|
| =/sys/cpu=            | percent busy                               |
| =/sys/ram=            | percent used                               |
| =/sys/disk=           | percent used of /                          |
| =/sys/disk/$@{mount}= | percent used of the filesystem holding it  |
| =/sys/temp=           | degrees C                                  |
| =/sys/load=           | =[1 5 15]=                                 |
| =/sys/uptime=         | seconds                                    |
| =/sys/user=           | login name                                 |
| =/sys/host=           | hostname                                   |

** /proc

Every running thing, whatever its blast radius. =(read /proc/*)= is the process
table; there is no second list anywhere.

| path                 | read                            | write                             |
|----------------------+---------------------------------+-----------------------------------|
| =/proc/?name=        | the declaration                 | declare it, and start it          |
| =/proc/?name/state=  | =:running= =:stopped= =:failed= |                                   |
| =/proc/?name/pid=    | the pid, when it has one        |                                   |
| =/proc/?name/out=    | a ring of its output            |                                   |
| =/proc/?name=        |                                 | =[:start]= =[:stop]= =[:restart]= |

A declaration is a map, and its one required key is the blast radius:

#+begin_src lisp
(write /proc/editor   {:image "pine editor"})
(write /proc/desktop  {:image "pine desktop"})
(write /proc/backup   {:run ["restic" "backup" "/home"] :every 3600})
(write /proc/notifier {:thread (fn () (loop (emit (poll)) (sleep 1)))})
#+end_src

| key       | means                                                |
|-----------+------------------------------------------------------|
| =:image=  | its own SBCL, joined to the system; faults come home  |
| =:run=    | a plain subprocess, argv                             |
| =:thread= | in the daemon, on its own thread                     |
| =:every=  | run it on an interval instead of keeping it up       |
| =:needs=  | paths that must be non-nil before it starts          |

Writing =/proc/?name= is idempotent and is how a thing stays alive: pine restarts
what it was told to run, backs off when it keeps dying, and stops it when the
path is written =nil=. There is no supervisor and no keep-alive flag, because a
declared process is one that is kept running by definition.

** /file, /sh, /env

The three doors onto Unix with no better provider. Prefer a provider's verb when
one exists: =(write /wm [:overview])= rather than shelling out to =niri msg=.
=/sh= is the escape hatch, not the habit.

| path            | read                    | write                     | watch               |
|-----------------+-------------------------+---------------------------+---------------------|
| =/file/$@{p}=   | contents                | write it; =nil= deletes   | inotify             |
| =/file/$@{dir}= | the directory, as a map |                           | inotify             |
| =/sh/${cmd}=    | run it, answer stdout   |                           | each line of stdout |
| =/sh=           | the ring of what ran    | =[:run ARGV...]= =[:sh STRING]= |               |
| =/env/?name=    | the variable            | set it                    |                     |

#+begin_src lisp
(read  /file/proc/uptime)
(write /file/tmp/note "hello")
(write /file/tmp/note nil)                       ; delete it
(read  /sh/${"hostname"})
(watch /sh/${"pactl subscribe"} #'refresh-audio)
(write /sh [:run "setsid" "-f" "alacritty"])     ; argv; nothing is shell-quoted
(write /sh [:sh  "cd ~ && emacsclient -c -n"])   ; when you want the shell's syntax
#+end_src

Reading and doing are different acts and take different forms, and in both the
value carries the information. Nothing ever writes =t= to mean "go".

** /audio, /screen, /power, /net, /media

| path                | read                                | write                    |
|---------------------+-------------------------------------+--------------------------|
| =/audio/volume=     | 0..100                              | set it                   |
| =/audio/muted=      | boolean                             | set it, =[:toggle]=      |
| =/audio/sink=       | the default sink                    | make one default         |
| =/audio/sinks/?n=   | ={:desc ..}=                        |                          |
| =/screen/brightness= | 0..100                             | set it                   |
| =/screen/outputs/?n= | ={:mode .. :scale ..}=             | set them                 |
| =/power/battery=    | 0..100                              |                          |
| =/power/state=      | =:charging= =:full= ...             |                          |
| =/power=            |                                     | =[:lock]= =[:logout]= =[:suspend]= =[:reboot]= =[:poweroff]= |
| =/net/connection=   | the active connection               |                          |
| =/net/online=       | boolean                             |                          |
| =/net/wifi/?ssid=   | ={:signal .. :secure .. :saved .. :in-use ..}= | =[:connect]= =[:disconnect]= =[:forget]= |
| =/net/wifi=         |                                     | =[:rescan]=              |
| =/media=            | ={:status .. :title .. :artist .. :art .. :position .. :length ..}= | =[:play]= =[:pause]= =[:next]= =[:previous]= |
| =/media/position=   | seconds                             | seek                     |

A secure network with no saved credential answers =[:connect]= by writing a
prompt to =/echo=. Nothing in a config ever asks for a password.

** /wm

The compositor, whichever it is. When pine is the window manager the same paths
answer, served by pine's own provider, and nothing above =/wm= changes.

| path                        | read                       | write          |
|-----------------------------+----------------------------+----------------|
| =/wm/workspaces/?n=         | ={:focused .. :urgent ..}= |                |
| =/wm/workspaces/?n/focused= | boolean                    | focus it       |
| =/wm/windows/?id=           | ={:title .. :app ..}=      |                |
| =/wm/focused=               | the focused window's path  | focus that one |
| =/wm=                       |                            | =[:overview]= =[:close]= =[:split :below]= =[:exit]= |

** /surface and /win

A surface is what wayland shows; a window is pine's own view onto a buffer. The
editor's tree is the arrangement, so the arrangement is paths and survives a
restart with no serializer.

| path                    | read          | write                                   |
|-------------------------+---------------+-----------------------------------------|
| =/surface/?name=        | the tree      | the tree                                |
| =/surface/?name/as=     | the placement | =:bar= =:panel= =:overlay= =:toplevel= =:background= =:echo= |
| =/surface/?name/shown=  | boolean       | show, hide, =[:toggle]=                 |
| =/surface/?name/anchor= |               | raw placement, when =:as= is not enough |
| =/win/?n/buf=           | a buffer path | show a different one                    |
| =/win/?n/scroll=        | first line    | scroll there                            |
| =/win/?n/weight=        | its share     | resize                                  |
| =/win/focused=          | a window path | focus one, =[:split :below]= =[:close]= =[:only]= |

** /buf

| path                         | read                      | write                             |
|------------------------------+---------------------------+-----------------------------------|
| =/buf/?name=                 | its map                   | create it                         |
| =/buf/?name/text=            | the whole string          | replace, or a verb                |
| =/buf/?name/line/?n=         | one line                  | replace it                        |
| =/buf/?name/line/${a}..${b}= | a seq of lines            |                                   |
| =/buf/?name/face/${a}..${b}= | their highlight runs      |                                   |
| =/buf/?name/point=           | =[line col]=              | move there                        |
| =/buf/?name/mark=            | =[line col]= or nil       | set it                            |
| =/buf/?name/file=            | the file it visits        | visit another                     |
| =/buf/?name/mode=            | a mode keyword            | change mode                       |
| =/buf/?name/minor=           | a set                     | =[:conj :paren]= =[:disj :paren]= |
| =/buf/?name/modified=        | boolean                   |                                   |
| =/buf/?name/tree=            | the parse tree            |                                   |
| =/buf/?name/view=            | a widget tree, if it has one | make it a tool buffer          |
| =/buf/current=               | a buffer path             | switch to one                     |

Text verbs: =[:insert TEXT]=, =[:delete FROM TO]=, =[:move UNIT N]=, =[:undo]=,
=[:redo]=, =[:save]=, =[:revert]=, =[:indent FROM TO]=, =[:kill]=.

The band that made a million line buffer work is not a policy in the parser any
more; it is what the window read. =/buf/main/face/**= is never asked for, so it
is never computed.

(read /buf/main/face/${top}..${bot})
#+end_src

*** Scope

Any leaf under a buffer with no value falls back to the same leaf at the root.
Buffer-local is not a mechanism; it is where the value is.

#+begin_src lisp
(write /tab-width 8)                    ; everywhere
(write /buf/foo.py/tab-width 4)         ; here
(read  /buf/scratch/tab-width)          ; => 8
#+end_src

** /echo

The minibuffer, as paths, so a command that prompts holds no callback and is
re-entrant.

| path           | read               | write         |
|----------------+--------------------+---------------|
| =/echo=        | the current prompt | a prompt map  |
| =/echo/hint=   | the hint line      | set it        |
| =/echo/result= | what was typed     |               |

#+begin_src lisp
(write /cmd/find-file
  {/echo {:prompt "Find file: " :complete :file :history :files
          :then   {/buf/current [:visit ${(read /echo/result)}]}}})
#+end_src

=:then= is a write-map, applied when the prompt is accepted.

** /log, /err, /doc

| path            | read                                           | write                          |
|-----------------+------------------------------------------------+--------------------------------|
| =/log=          | the last line                                  | append                         |
| =/log/*=        | the ring                                       |                                |
| =/err/?id=      | ={:condition .. :restarts .. :at .. :root ..}= | =[:restart :abort]=            |
| =/doc/$@{path}= | what that path is, and what it takes           |                                |

A fault in any image parks at =/err= rather than unwinding, carrying the root it
faulted under. The debugger is a surface over =(read /err/*)= that writes a
restart name to the one you pick, and it works across images because a fault on
another host lands at =/host/arraniz/err= and reads identically.

* Modes

A mode is a map. Everything declarative is a leaf; everything behavioural is a
handler. There is no class, no =defmode= and no registration step, because
writing it is the registration.

#+begin_src lisp
(write /mode/prog
  {:parent  :text
   :indent  {:width 2}
   :comment {:line ";"}})

(write /mode/lisp
  {:parent    :prog
   :grammar   :commonlisp
   :indicator "Lisp"
   :files     ["*.lisp" "*.asd" "*.cl"]
   :comment   {:line ";;"}
   :indent    {:width 2 :special {"defun" 2 "let" 1 "loop" 0}}
   :on        {:newline (fn (buf) {/buf/${buf}/text [:newline]
                                   /buf/${buf}      [:indent-line]})}})
#+end_src

| key          | is                          |
|--------------+-----------------------------|
| =:parent=    | the mode it falls back to   |
| =:grammar=   | the tree-sitter language    |
| =:indicator= | the mode line text          |
| =:files=     | which files get it          |
| =:comment=   | comment syntax              |
| =:indent=    | indent data                 |
| =:on=        | verb to handler             |
| =:view=      | a tool buffer's widget tree |

** Dispatch

A verb written to a buffer resolves by lookup, not by method combination:

1. each minor mode in =/buf/?name/minor=, in =/minor/?m/precedence= order
2. the major mode, then its =:parent=, up the chain
3. the built-in verb

The first =:on= entry wins, which makes the whole dispatch readable:

#+begin_src lisp
(read /mode/lisp/on/*)         ; exactly what lisp-mode overrides
(read /mode/**/on/newline)     ; every mode that touches newline, in one map
#+end_src

** A minor mode

#+begin_src lisp
(write /minor/paren
  {:precedence 10
   :indicator  "()"
   :on {:insert (fn (buf text)
                  (if (member text '("(" "[" "\"") :test #'equal)
                      {/buf/${buf}/text  [:insert ${(close-for text)}]
                       /buf/${buf}/point [:move :char -1]}
                      {}))}})

(write /buf/*{:mode :lisp}/minor [:conj :paren])
#+end_src

** A tool buffer

A mode with a =:view=. This is the process list, complete. It has no state of its
own, because the state is =/proc=.

#+begin_src lisp
(write /mode/proc-list
  {:indicator "Proc"
   :view (fn (buf)
           (column :class :tool
             (label "process" :class :tool-title)
             (rows /proc/*
               (fn ()
                 (choice :class (case (read ./state)
                                  (:running :ok) (:failed :bad) (t :idle))
                         :click {. [:restart]}
                   (row (label (leaf .) :expand 1)
                        (label (string (read ./state)) :class :tool-dim)
                        (label (or (read ./pid) "")    :class :tool-dim)))))))
   :on {:activate (fn (buf) {${(read /buf/${buf}/selection)} [:restart]})
        :delete   (fn (buf) {${(read /buf/${buf}/selection)} nil})}})

(write /cmd/list-processes
  {/buf/*proc*     {:mode :proc-list}
   /win/focused/buf /buf/*proc*})

(write /key/global/C-c/p /cmd/list-processes)
#+end_src

The view re-renders when =/proc= moves, by the one rule. Nothing polls, nothing
subscribes, and the buffer holds no copy of the table.

* Keys

A key sequence is a path, because a prefix map is a directory. A binding's value
is a command path, a handler, or a write-map.

#+begin_src lisp
(write /key/global/C-x/C-f /cmd/find-file)
(write /key/global/C-c/s   {/win/focused/buf /buf/scratch})
(write /key/wm/s-Return    {/sh [:run "alacritty"]})
(write /key/global/C-x/C-f nil)                    ; unbind
(read  /key/global/C-x/*)                          ; the prefix map
(read  /key/**{= /cmd/find-file})                  ; where is this bound
#+end_src

A whole map at once:

#+begin_src lisp
(write /key/mode/dired
  {m /cmd/dired-mark  d /cmd/dired-delete  RET /cmd/dired-visit})
#+end_src

The =/key= provider normalizes a chord on write, so =C-M-x= and =M-C-x= are one
path and there is no aliasing to remember. The window manager registers exactly
what is under =/key/wm= with the compositor; there is no second list of chords.

* Commands

A command is a path holding a handler or a write-map. Writing it defines it, M-x
reads the directory, keys bind to it, widgets click it.

#+begin_src lisp
(write /cmd/scratch  {/win/focused/buf /buf/scratch})
(write /cmd/save-all {/buf/*{:modified t :file (not (null %))} [:save]})
(write /cmd/balance  {/win/*/weight 1})
(write /cmd/rename
  {/echo {:prompt "New name: " :then {/buf/current/name ${(read /echo/result)}}}})
#+end_src

* Content

The widget language: functions that build a tree, written to a =/surface= path or
to a mode's =:view=. They build maps, so an unchanged subtree is the same object
and the frontend diff never descends into it.

| containers | =column= =row= =centerbox= =center= =box= =scroll= =grid= =stack= |
| content    | =label= =icon= =image= =rule= =gap=                               |
| controls   | =button= =slider= =ring= =field= =choice= =rows=                  |
| views      | =window= =terminal= =modeline= =echo= =calendar=                  |

Shared keywords: =:class= =:face= =:align= =:spacing= =:expand= =:width=
=:height=.

** Three rules, and they are what empty a config of handlers

*** A slot takes a path in place of a value

#+begin_src lisp
(label /media/title)
(image /media/art)
(label (format nil "~d%" (read /audio/volume)))
#+end_src

*** A control takes the path it edits as its subject

#+begin_src lisp
(slider /audio/volume      :min 0 :max 100)
(slider /screen/brightness :min 0 :max 100)
(slider /media/position    :min 0 :max (read /media/length))
#+end_src

Dragging writes the path. There is no =:value= and no =:on-change=: the display
and the edit are one path, and the provider decides what a write means.

*** Something that acts takes writes

#+begin_src lisp
(button :click /cmd/scratch (label "scratch"))
(icon #x0F04B :click {/media [:play]})
(icon #x0F011 :click {/power [:poweroff]} :confirm "Power off?")
#+end_src

=:click= takes a command path, a write-map, or a =fn=. =:confirm= gates the write
on an answer, so no config carries a confirm state machine.

*** rows

=rows= maps over a pattern or a seq, and =.= is the row's path.

#+begin_src lisp
(rows /net/wifi/*
  (fn ()
    (choice :click {. [:connect]}
      (row (icon #x0F1EB :class (signal-class (read ./signal)))
           (label (leaf .) :expand 1)
           (label (if (read ./secure) "*" ""))))))
#+end_src

* Its place in Common Lisp

The DSL is not the extension language. CL is. The namespace is where state lives,
and that is the whole relationship.

A package is an ASDF system that depends on =pine=, and it takes one of three
shapes, or several:

| you are wrapping a system nothing models | write a provider under a new path |
| you are presenting state that exists     | write a mode with a =:view=       |
| you are adding an act                    | write a command, bind a key       |

Everything else is ordinary CL. The one thing pine asks is that state you want
the system to know about goes in the namespace rather than in a global. Nothing
stops you using =defvar=; what you give up is that the value is not inspectable,
not persisted, not undoable and not reachable from another image.

** A dired, whole

#+begin_src lisp
;;;; pine-dired.asd
(defsystem "pine-dired"
  :depends-on ("pine")
  :components ((:file "dired")))
#+end_src

#+begin_src lisp
(defpackage :pine-dired (:use :cl :pine))
(in-package :pine-dired)
(named-readtables:in-readtable pine:syntax)

;;; Plain CL. Most of a package is this.

(defun human (n)
  (cond ((null n) "")
        ((> n 1073741824) (format nil "~,1fG" (/ n 1073741824.0)))
        ((> n 1048576)    (format nil "~,1fM" (/ n 1048576.0)))
        ((> n 1024)       (format nil "~dK"   (round n 1024)))
        (t                (format nil "~d"    n))))

(defun perms (bits) ...)

(defun ordered (entries by)
  (sort (keys entries)
        (ecase by
          (:name #'string<)
          (:size (fn (a b) (> (read (path a :size))  (read (path b :size)))))
          (:time (fn (a b) (> (read (path a :mtime)) (read (path b :mtime))))))))

;;; State, on the buffer that shows it. No globals, no registry, no list of
;;; dired buffers.
;;;   /buf/?name/dir     the directory shown
;;;   /buf/?name/marks   a set of file paths
;;;   /buf/?name/sort    :name | :size | :time

(defun view (buf)
  (let* ((dir   (read /buf/${buf}/dir))
         (marks (read /buf/${buf}/marks #{}))
         (files (read /file/$@{dir}/*)))
    (column :class :dired
      (row (label dir :class :dired-title)
           (gap)
           (label (format nil "~d files, ~a" (size files)
                          (human (reduce #'+ (vals files) :key (fn (e) (:size e)))))
                  :class :dired-dim))
      (rows (ordered files (read /buf/${buf}/sort :name))
        (fn ()
          (let ((marked (contains? marks .)))
            (choice :class (if marked :dired-marked :dired-row)
              (row (label (if marked "*" " ")   :class :dired-mark)
                   (label (perms (read ./mode)) :class :dired-perms)
                   (label (human (read ./size)) :class :dired-size :width 7)
                   (label (leaf .) :expand 1
                          :class (if (read ./dir) :dired-dir :dired-file))))))))))

;;; Acts. Each answers writes and performs nothing, so each is testable by
;;; calling it and comparing a map.

(defun selected (buf) (read /buf/${buf}/selection))

(write /cmd/dired-mark
  (fn (buf)
    (let ((p (selected buf)) (marks (read /buf/${buf}/marks #{})))
      {/buf/${buf}/marks ${(if (contains? marks p) (less marks p) (with marks p))}
       /buf/${buf}/point [:move :line 1]})))

(write /cmd/dired-delete
  (fn (buf) (fold (read /buf/${buf}/marks) {} (fn (m p) (with m p nil)))))

(write /cmd/dired-copy
  (fn (buf dest)
    (fold (read /buf/${buf}/marks) {}
          (fn (m p) (with m /file/$@{dest}/${(leaf p)} (read p))))))

(write /cmd/dired-visit
  (fn (buf)
    (let ((p (selected buf)))
      (if (read (path p :dir))
          {/buf/${buf}/dir ${p} /buf/${buf}/marks #{}}
          {/buf/${(leaf p)}  {:file ${p}}
           /win/focused/buf /buf/${(leaf p)}}))))

(write /mode/dired
  {:indicator "Dired"
   :view      #'view
   :on        {:activate #'dired-visit}})

(write /key/mode/dired
  {m /cmd/dired-mark  d /cmd/dired-delete  c /cmd/dired-copy
   s /cmd/dired-sort  RET /cmd/dired-visit})

(write /cmd/dired
  {/echo {:prompt "Directory: " :complete :dir
          :then {/buf/*dired*   {:mode :dired :marks #{} :dir ${(read /echo/result)}}
                 /win/focused/buf /buf/*dired*}}})

(write /key/global/C-x/d /cmd/dired)
#+end_src

Three things worth noticing.

There is no refresh command. =view= reads =/file/$@{dir}/*=, the file provider
watches with inotify, and the view rebuilds by the one rule.

Deleting is writing =nil= and copying is a read and a write, so copying to
another machine is the same function with a different destination path, and
nobody wrote networking.

Marks are a set at a path, so they are held and survive a restart, they are
visible to anything else, and another image can mark files in your dired.
